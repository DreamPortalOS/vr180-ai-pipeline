# 覆盖方案 v2：让 180° 视野里的主要内容都是"真生成"的

> lead 合成稿（2026-09-07）。材料来自三路独立调研（v360 鱼眼几何与自校准；AI 视频广角/鱼眼提示词实证；显示侧），
> 以及仓内已固化的数学与 owner 实测。额度中断导致"视频外扩"与"深度重投影"两路只回来部分材料，
> 对应小节标 **[部分查实]**。数字一律用针孔正确公式 `px/deg(轴上) = (W/2)/tan(hfov/2)·π/180`。

## 0. 结论先行

**首选路线：原生 1:1 宽视角前进素材（Seedance std 4k，2880²，hfov 115–120°）+ 现有 feather。**
- 180° 里真生成内容占比：约 **115°×115°**（面积占半球 ≈ 55%，且**覆盖 Quest 3 的 110°×96° 视场**——正视时看不到边）
- 清晰度：hfov 115 → **16.0 px/度**（与输出零损）；hfov 120 → 13.7
- 耗时/额度：一次 Seedance 4k 调用（10–15 s）；管线不变
- 代价：横向比现在的 126° 少 6–11°，转头到极限时会提前碰到渐隐区（feather 已定版，边界是黑色渐隐而非白边）

**备选路线：鱼眼源 + `v360 input=fisheye`。** 能到 180°×180° 全覆盖且**角分辨率均匀**（2880 px @180° = 16 px/度处处一致），
但 AI 生成的"鱼眼"是风格化的、不保证等距投影几何（三篇论文一致结论），需要自校准或退化为"当作 150–170° 用"。
**先做首选，把备选留作下一轮实验。**

**owner 的思路（先渲 16:9 再裁 1:1 再升采样）：不推荐，见 Q0。**

## Q0. 「先渲 16:9，裁 1:1，再升采样」为何不增加覆盖角

裁剪只能**丢掉**视野，不能增加：16:9 源在 hfov 70° 时纵向 43°，裁成 1:1 后横向也只剩 43°——
覆盖从 70°×43° 变成 **43°×43°**，比现在更小。升采样把 43° 铺到更多像素，**角度一分不涨**（像素/度变高，但边界还在 43°）。
覆盖角只由**源片本身画了多大的视野**决定。要 1:1 的宽覆盖，就得让模型**直接生成 1:1 的宽视角画面**。

## QA. 原生 1:1 宽视角（首选）

### 数字（源 2880×2880）

| hfov（=vfov） | 覆盖 | 轴上 px/度 | 对 16 px/度 | 备注 |
|---|---|---|---|---|
| 110 | 110°×110° | 17.6 | 无损 | 恰好等于 Quest 横向视场，转头即碰边 |
| **115** | 115°×115° | **16.0** | **零损** | 推荐起点（= YouTube 5.7K VR180 交付密度） |
| **120** | 120°×120° | 13.7 | 放大 1.17× | 推荐上限 |
| 126 | 126°×126° | 12.8 | 放大 1.25× | 与现在横向相同、纵向 +30° |
| 130 | 130°×130° | 11.7 | 放大 1.37× | 开始明显软 |

注意：矩形透视画面**采样密度最低点在画面中心**（`dx/dα = f·sec²α`），飞行素材里你盯得最久的消失点正是最软处，
所以 hfov 每提一档，中心锐度代价超线性——这就是不建议超过 120 的原因。

### 模型能否被 prompt 出真广角？

- **官方词汇表（Seedance 2.0/2.5 提示词指南）没有任何 广角/鱼眼/焦距/畸变 词条**，只有景别与运镜；2.5 指南给的通用规则是
  「小众专业名词 → [名词 + 描述性解释]」。API 无任何 FOV 参数，只有 `camera_fixed`。
- 社区实测最有效的措辞（Seedance）：
  - `first-person POV, the camera IS the eyes, wide-angle lens (strong distortion), subtle chromatic aberration near frame edges`
  - `Filmed with chest mounted GoPro, fisheye distortion at the edges`（"点名设备"比"POV"有效得多）
  - 中文：`第一人称 / FPV 视角 / 大广角镜头 / 俯冲`（2.5 官方词表含 FPV、第一人称、俯冲）
- **学术结论一致**：文字里的镜头词是"风格近似"，不校准（Curved Diffusion ECCV'24：prompt fisheye 只是"rudimentary approximation"，"not feasible for VR"；Generative Photography CVPR'25、Camera-Settings-as-Tokens SA'24 同）。
  **没有任何公开基准测过 T2V 模型输出的真实 hfov。**
- 因此：**hfov 必须按片校准**，不能信 prompt。校准法见 QB 表（AnyCalib/GeoCalib，Apache，12GB 轻松）；
  或最便宜的：用 `v360 output=flat` 扫几档 `ih_fov`，看地平线/立柱是否变直。

### 首选路线的生成规格与 prompt

| 项 | 值 |
|---|---|
| 模型 | `doubao-seedance-2-0-260128`（标准档；`--model` 已解锁 #246） |
| ratio / resolution | `1:1` / `4k` → 2880×2880（10bit HEVC，管线先做解码冒烟） |

```
一镜到底的第一人称飞行长镜头，超广角镜头（明显的透视拉伸，画面四角物体被拉宽，地平线偏低，近大远小夸张）。
镜头以恒定速度持续向前推进，从头到尾不停、不减速、不后退、不切换机位、不做任何转场。
主体与运动：一条向前延伸的峡谷通道，两侧层叠巨型岩壁与悬空植被，前方远处一个明亮开口作为消失点，镜头始终朝它飞。
```

自检（不过关直接重生成）：① `ffprobe` 确认 2880×2880；② 光流径向散度为**正**且随半径增大（静态机位会是 ≤1 px 且为负）；
③ 用 `v360 output=flat` 扫 `ih_fov` 找让地平线最直的值，**以此为 `--src-hfov`**，别信 prompt 里写的度数。

## QB. 鱼眼源 + `v360 input=fisheye`（备选）

- **几何已从 ffmpeg 源码核实**：`input=fisheye` 是**等距鱼眼**（r ∝ θ，f-theta），`ih_fov/iv_fov` 是跨整帧的全角；
  1:1 帧、圆内切时 `ih_fov=iv_fov=180`。**不要传 `id_fov=180`**（方形帧会变成 127.3°）；`output=hequirect` 忽略 `h_fov/v_fov`，固定 ±90°。
- 完整参数串（2880² 圆形 180° 鱼眼 → 2880² hequirect）：
  `v360=input=fisheye:output=hequirect:ih_fov=180:iv_fov=180:w=2880:h=2880:interp=lanczos`
  立体：每眼一次再 `hstack`，再注 sv3d/st3d。若只画了 150°：`ih_fov=150:iv_fov=150` + `alpha_mask=1`（注意 alpha 掩码是**方形**可见性，不是圆）。
- **角分辨率均匀**：等距鱼眼 px/度 = D/FOV，处处相同：2880 @180° = 16.0；@150° = 19.2；4096 @180° = 22.8。
  这是鱼眼路线相对矩形透视的根本优势（后者中心最稀）。
- **风险：AI 鱼眼不是等距**。按等距解析等立体角/体视鱼眼会把 50° 处的物体放到 42–54°（误差 ±4–8°，中心与边缘正确、中场最差），
  转头时世界"橡皮布"式错位，双眼还会引入垂直视差。v360 **没有**多项式/Kannala-Brandt 模型，需要先用 `remap` 纠正。
- 自校准可选（均 12GB 轻松）：**AnyCalib**（Kannala-Brandt kb:4，Apache）、**GeoCalib**（Apache，≈0.5 GB 显存）；
  最便宜：让生成器画网格/地平线，`v360` 分别按 `fisheye/equisolid/sg/og` 反投到 `flat` 扫 `ih_fov`，选直线最直的模型。
- 生成侧实证：Veo 3.1 **图生视频会保留输入鱼眼几何**（Google DevRel 实测）；Wan 认识 "fisheye"；开源侧有鱼眼 LoRA（说明 prompt 单独不稳）。
- Seedance 鱼眼提示草案：`圆形鱼眼镜头效果（180° 视角，画面为内切于正方形的圆，圆外纯黑），画面边缘强烈的球形扭曲，
  第一人称持续向前飞行……`；或按官方机制**上传真实鱼眼 FPV 片段写「参考@视频1的运镜」**。

## QC. 视频外扩把 16:9 补成 1:1 [部分查实]

- **Seedance 官方策略是裁剪不是补全**：图生视频比例不一致时"居中裁剪"。把 16:9 首帧贴进 1:1 黑底再喂 `ratio=1:1`，
  黑边会被当作首帧内容条件化——**无任何公开案例说明它会"画满"黑边**，需一次 480p/4s 探针实测（**未证实**）。
- Veo 3.1：黑边**会被保留**（DevRel 反过来利用它做方形视频）；Kling：相框会被当内容并诱导"画框展览"运镜；Wan FAQ 建议事后裁剪/填黑。
- 可做外扩的模型：**PanoWan**（Wan2.1-1.3B LoRA，零样本视频外扩到 ERP；基座 8.19 GB 显存）、**Imagine360**（透视→360，SD 基座）。
  Follow-Your-Canvas / Be-Your-Outpainter / ComfyUI 工作流的显存与一致性口碑**本轮未查实**（额度中断）。
- 判断：作为"真生成"手段有希望（1.78× 面积远低于文献失效的 9×），但**先于首选路线验证 QA 更划算**。

## QD. 深度重投影合成前进 [部分查实]

- 12GB 可跑的全景视频生成：**Matrix-3D 5B 低显存模式 12G**（输出 960×480 / 1440×720 ERP = 2.7–4 px/度，比 16 差 4–6 倍；
  且整链最低 16G，因为 Text2PanoImage 阶段 ~16g——除非自带全景图）；PanoWan（1.3B）。HunyuanWorld-Voyager 60GB 出局。
- 3D Photo / 分层深度 / Gaussian splat 路线的逐帧耗时与"真前进 vs 视差晃动"口碑**本轮未查实**。
- 判断：分辨率天花板太低，**不作为主线**。

## 风险与退路

- ~~管线能否吃 Seedance 4k 的 10bit HEVC~~ ✅ 已实证可以（#298，CI 每次都跑）。
- 首选路线的最大不确定：**模型是否真听"持续前推 + 超广角"**（官方无 FOV 参数、无相机运动 API）。用 `draft` 先试，量光流再花 4k 额度。
- hfov 不可信 → 必须校准（C-1），否则几何错位比白边更难受。
- 若 1:1 宽视角效果不佳 → 备选鱼眼路线（QB）；若两者都不行 → QC 视频外扩探针。
