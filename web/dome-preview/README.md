# Dome Preview — domemaster 覆盖度预览器

在**出片之前**把一张 domemaster 母版贴到半球内表面上，量出它到底铺到天顶角多少度、
外圈留了多少白。

起因：一版 4096² 球幕母版内容只铺到半径 0.6，外圈 0.8–0.98 仅 8.2% 有内容 ——
这件事是在花掉生成费用、渲染 35 分钟之后才发现的。这个工具就是为了让它在渲染前 10 秒钟被发现。

## 怎么打开

**不需要 npm install，不需要构建，不需要联网。** 只有 `index.html` + 4 个 JS 文件，
用的是浏览器自带的 WebGL，没有任何第三方运行时依赖。

```bash
# 推荐：从仓库根目录起一个静态服务（这样 video/ 里的素材也能直接拖进来）
python -m http.server 8000
# 然后浏览器打开 http://localhost:8000/web/dome-preview/
```

也可以**直接双击 `index.html`**。3D 视图、参数面板、投影仪示意在 `file://` 下都能用；
但部分浏览器在 `file://` 下会拒绝读取画面像素（canvas 安全策略），
这时覆盖度读数会提示你改用上面那条 `http.server` 命令。

加载素材：点「选择 domemaster 图 / 视频」，或者**把文件直接拖进窗口**。
图片和视频都支持（视频按空格键播放 / 暂停，播放时读数每 0.5 秒刷新一次）。

## domemaster 语义约定

本工具按**标准 fulldome domemaster（方位等距 / azimuthal equidistant，180° 半球）** 解释画面，
与 `_research/dome_venue/VENUE_ANALYSIS.md` 认定的交付格式一致：

| 画面上的位置 | 球幕上的位置 |
|---|---|
| 正方形画面的**内切圆** | 完整的 180° 半球 |
| 圆心 | **天顶**（正上方） |
| 圆周 | **地平线 / 起拱线** |
| 归一化半径 `r`（0→1） | **天顶角 `θ = r × 90°`，线性对应** |
| 圆的**下边缘**（画面 6 点钟方向） | 球幕**正前方**（观众朝向） |
| 内切圆之外的四个角 | 不显示，属于浪费的像素 |

「画面下边缘 = 正前方」是 IMERSA Dome Master 行业惯例。
场馆文档从未写死这条约定，交付前必须与对方书面确认 —— 详见 `VENUE_ANALYSIS.md` §2.4。

3D 里的坐标约定：`+Y` = 天顶，`-Z` = 球幕正前方，`y=0` 平面 = 起拱线。

## 覆盖度读数怎么算的

把画面缩到 512×512，按到圆心的归一化半径分成 256 个圆环，统计每个环上「有内容」的像素比例
（`有内容` = 亮度 ≥ 亮度阈值，默认 4/255，可在面板上调）。然后从最外圈往里走：

- **实心天顶角**（大号读数）：最外侧那个「环上 ≥98% 的像素都有内容」的半径 × 90°。
  这是**球幕开始变黑的那个角度**，也是真正要盯的数。
- **含羽化最外沿**：把判据放宽到 ≥50%，用来看有没有渐隐 / vignette 拖尾。
  两个数差得远，说明母版边缘是羽化掉的而不是硬切的。
- **外圈 0.80–0.98 有内容**：就是当初翻车的那一圈，低于 50% 标红。
- **圆内有效像素**：内切圆内有内容的像素占比。
- **覆盖立体角**：`1 − cos θ`，即实际被照亮的半球立体角占比。
  注意它比天顶角更残酷 —— 60° 的天顶角只覆盖半球的一半。
- 下方柱状图是**逐半径的填充率曲线**，红色竖条标出 0.80–0.98 那一圈，黄线标出实心边界。

3D 视图里，超出实心边界的部分会打上**红色斜纹**，边界本身画成一条黄环 ——
直接就能看见母版在球幕上会空出多大一圈。（可用「标注留白」按钮关掉。）

### 实测参照

| 素材 | 实心天顶角 | 实心半径 r | 含羽化 | 外圈 0.80–0.98 | 覆盖立体角 |
|---|---|---|---|---|---|
| `video/dome_seed_test.png`（合规球幕图） | **84.4°** | 0.938 | 84.7° | 79.3% | 90.2% |
| `video/dome_v10_4096.mp4` @ t=5s | **60.1°** | 0.668 | 65.0° | **8.8%** | 50.2% |

后者的「外圈 8.8%」与 owner 当初手工量出的 8.2% 基本吻合，可以当作这套读数的校验。
两份素材的读数差出 24°，翻车的那一版一眼就能认出来。

## 场馆参数

默认值取自 `_research/dome_venue/VENUE_ANALYSIS.md`（Fulldome.pro 12 m 负压球幕）：

| 参数 | 默认 | 出处 |
|---|---|---|
| 穹顶直径 | **12 m** | 【实】报价单 12 m 球幕本体 |
| 倾角 tilt | **0°** | 【推】文档未载明；结构爆炸图显示起拱线水平，按 0° 起算，**必须向对方确认** |
| 观众眼高 | **1.20 m** | 【推】坐姿眼高；文档未载明。站姿可拉到 1.6 m 左右 |

改直径 / 倾角 / 眼高，3D 视图实时更新。「恢复场馆默认」一键回到 12 m / 0° / 1.20 m。

## 投影仪示意

8 台 = **下环 5 台（方位每 72°）+ 上环 3 台（每 120°，偏置 36°）**，
数字出自 [A p.12] / [B p.15] 的 `Projection layout 8 (5+3) pcs`。

**这是示意图，不是标定数据。** 厂家从未提供 12 m 球的真实投影布局图、
融合带宽度、方位基准，所以这里只画了：机位在起拱线一圈的塔架上、朝对侧交叉投射、
下环打低仰角带、上环打高仰角到天顶。锥体张角是画着好看的固定值。
真要对位，必须先向对方索取 12 m 的实际布局图（见 `VENUE_ANALYSIS.md` §2.3 的风险提示）。

## 操作

| 操作 | 效果 |
|---|---|
| 拖动 | 观众位 = 转头；外部俯视 = 旋转 |
| 滚轮 | 外部俯视 = 缩放；观众位 = 改 FOV |
| 空格 | 视频播放 / 暂停 |
| 拖放文件 | 加载素材 |

「观众位」把相机放在球心正下方的眼高处，能转头看；「外部俯视」从外面看整个球，
适合一眼判断留白有多大。

## 文件结构

```
web/dome-preview/
├── index.html      # 界面 + 样式（无外部资源）
├── README.md
└── js/
    ├── glkit.js    # mat4 + WebGL 着色器/缓冲小工具
    ├── geometry.js # 半球网格、经纬网格、地面、投影仪机位
    ├── coverage.js # 覆盖度测量（纯 2D canvas，可单独复用）
    └── main.js     # 应用装配：相机、参数、素材加载、读数
```

### 为什么没用 Three.js

卡片允许 CDN 或 vendored 单文件，两条路各有问题：CDN 离线打不开（也过不了国内网络），
vendored 要往仓库里塞一个几百 KB 的第三方 bundle 并额外处理许可声明。
这个预览器真正需要的只有「一个带贴图的半球 + 几条线 + 一个轨道相机」，
直接用 WebGL 写下来比引依赖还短，于是零依赖：**双击就能开，离线可用，
不增加任何 license 负担**。`coverage.js` 也因此完全独立于渲染，可以直接搬去别处用。
